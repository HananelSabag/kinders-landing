## 3. מסר וטון

- **רעיון מרכזי (טיוטה):** *"כל ילד ראוי לצעצוע משלו"*
- **תת-כותרת (טיוטה):** *"אנחנו אוספים צעצועים, מחדשים אותם באהבה ומעניקים אותם לילדים במסגרות חירום, לזכר ילדי הקינדרטרנספורט."*
- **טון:** חם, מלא תקווה ומכבד. **לא רחמים ולא אשמה.** הילדים הם לא "מסכנים", הם ילדים שמגיע להם צעצוע.
- **הסיפור ההיסטורי [D9]:** בשנים 1938–39 חולצו כ-10,000 ילדים, כל אחד עם מזוודה קטנה אחת, ולפעמים עם דובי. לזכרם, אנחנו דואגים שלכל ילד יהיה צעצוע משלו. **בקצרה ובעדינות, לא בכותרת הראשית.**

### עקרונות אנימציה ("לא להגזים")
- ✅ חשיפה עדינה בגלילה (fade + 8–16px) · מונה מספרים שעולה פעם אחת · מעבר hover על כרטיסים · **רגע חתימה אחד בלבד**
- ✅ כיבוד `prefers-reduced-motion`: מי שביקש, לא יראה תנועה
- ❌ בלי scroll-jacking, בלי parallax כבד, בלי וידאו אוטומטי עם קול, בלי חלקיקים או תלת-ממד
- כלל אצבע: **אם מורידים את האנימציה והדף עדיין עובד מצוין, היא במקום.**

### 6.3 "השארת מקום" לסליקה: שכבת ספק מופשטת
```ts
// src/lib/payments/types.ts
export type DonationFrequency = 'one_time' | 'monthly';

export interface CreateDonationInput {
  amountIls: number;
  frequency: DonationFrequency;
  donor?: { name?: string; email?: string; phone?: string };
}

export interface CreateDonationResult {
  redirectUrl: string;      // לאן שולחים את התורם (דף מאובטח של הספק)
  providerRef?: string;
}

export interface DonationEvent {   // מה שחוזר מה-webhook
  providerRef: string;
  status: 'succeeded' | 'failed';
  amountIls: number;
  frequency: DonationFrequency;
  receiptUrl?: string;
}

export interface PaymentProvider {
  id: 'link' | 'mock' | 'grow' | 'cardcom' | 'morning' | 'nedarim';
  createDonation(input: CreateDonationInput): Promise<CreateDonationResult>;
  parseWebhook?(req: Request): Promise<DonationEvent>;
}
```
| ספק בקוד | מתי | מה הוא עושה |
|---|---|---|
| `whatsapp` | **ברירת מחדל (MVP)** | מעביר לוואטסאפ של העמותה עם הודעה מוכנה (סכום + חד-פעמי/חודשי) |
| `mock` | פיתוח | מדמה הצלחה ומפנה ל-`/thank-you` |
| `link` | **MVP** | מפנה ל-URL קבוע של דף תשלום (או Bit) מתוך משתנה סביבה |
| `grow` / `cardcom` / ... | **Phase 2** | קריאת API אמיתית + webhook |

ההחלפה בין ספקים נעשית **רק דרך משתנה סביבה** (`PAYMENT_PROVIDER=link`), בלי לגעת ב-UI.
```
# .env.example
PAYMENT_PROVIDER=whatsapp        # whatsapp | mock | link | grow | cardcom | morning | nedarim
PAYMENT_LINK_URL=                # ל-provider=link
NEXT_PUBLIC_SITE_URL=            # מספר הוואטסאפ עצמו נמצא ב-src/content/site.ts
# Phase 2 (לפי הספק שייבחר):
# GROW_USER_ID= / GROW_PAGE_CODE= / GROW_API_KEY=
# SUPABASE_URL= / SUPABASE_SERVICE_ROLE_KEY=
```
**כלל ברזל:** פרטי אשראי **לעולם לא** עוברים דרך השרת שלנו. רק דף או iframe של הספק (PCI).

### 6.4 RTL ועברית
- `<html lang="he" dir="rtl">` · רק **logical properties** של Tailwind (`ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-`)
- אייקונים עם כיוון (חצים) מתהפכים · מספרים ומספרי טלפון ב-`dir="ltr"` כשצריך
- גופנים דרך `next/font/google` עם `subsets: ['hebrew','latin']`

### 6.5 SEO ושיתוף
- `metadata` מלא + **תמונת OG בעברית 1200×630**. זה **קריטי** כי רוב התנועה תגיע משיתופים בוואטסאפ ובפייסבוק
- JSON-LD מסוג `NGO` · `sitemap.xml` · `robots.txt`

### 6.6 איכות (תנאי "סיום")
- Lighthouse בנייד: Performance ≥ 95, Accessibility = 100
- אפס הפרות axe · עבודה מלאה במקלדת · ניגודיות ≥ 4.5:1
- נבדק ב-**375px**, ‏768px ו-1440px · נבדק עם `reduced-motion`
- `web-design-guidelines` + `impeccable audit` עוברים בלי ממצאים קריטיים

## 9. כללים שאסור לשבור
1. ❌ **לא לכתוב "מוכר לצורכי מס" / "סעיף 46"** עד שיש אישור.
2. ❌ **לא להציג פנים של ילדים.** טשטוש, צילום מהגב, ידיים או צעצועים.
3. ❌ **לא לאחסן פרטי אשראי.** רק דף של ספק.
4. ✅ כל מספר השפעה **מאומת מול העמותה**. לא ממציאים.
5. ✅ אנימציה משרתת את המסר, ולא להפך.
